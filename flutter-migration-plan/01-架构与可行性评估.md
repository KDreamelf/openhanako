UI 调业务核心是直接函数调用，无 HTTP/WS 序列化开销；CLI/Server 模式共用同一份 `lib/core/`。

## 1.3 三条路径回顾（决策已做）

| 路径 | 描述 | 决策 |
|------|------|------|
| **Option A** | 全 Dart 重写 | **✅ 选定** |
| Option B | Flutter UI + 保留 Node 后端 | ❌ 不选 |
| Option C | 在 Electron 内嵌 Flutter | ❌ 不选 |

### 选 Option A 的成本与收益

**收益**：
- 单语言、单二进制、单进程
- 安装包从 ~150MB 降至 ~60MB
- 冷启动 3-5s → 1-2s
- 主窗口空载内存 ~250MB → ~80MB
- 业务核心可与 UI 直接共享，无 IPC 开销
- 一份 `lib/core/` 出 GUI / CLI / Server 三种形态
- Dart 强类型 + sealed class 天然规避 JS 弱类型 BUG（如 BUG-2）
- 无 Node.js 运行时依赖（macOS 用户不再纠结 brew node 版本）

**成本**：
- ~11K LOC 业务逻辑迁移
- Pi SDK 完全重写（最大单项）
- skills2set 现有 skill 兼容性（breaking change，需迁移期）
- 文档解析（mammoth/exceljs）的 Dart 等价品功能弱
- macOS 公证流程仍要重新搭

## 1.4 关键技术决策清单

| 决策点 | 选择 | 理由 |
|--------|------|------|
| **多窗口** | `desktop_multi_window` | 见 [02 章节](./02-多窗口实现方案.md) 详细对比 |

| **路由** | go_router | 多窗口下每个窗口独立 router |
| **数据库** | **Drift（含 native sqlite3）** | better-sqlite3 → Drift schema 平滑迁移；类型安全；纯 Dart 无 native rebuild |
| **HTTP** | dio | 拦截器/取消/进度齐全；支持 SSE 流式 |
| **WebSocket** | web_socket_channel | UI 端 WS 客户端（仅 server 模式或 IM bridge 用） |
| **Markdown** | flutter_markdown + markdown | 自定义 builder 处理代码块 |
| **代码编辑器** | re_editor + re_highlight | CodeMirror 6 替代 |
| **YAML** | yaml + yaml_edit | 解析 + **原文修改保留注释** |

| **Telegram** | teledart | 主流 Dart Telegram bot 客户端 |
| **飞书 / WeCom** | 直接 HTTP（dio） | 无官方 Dart SDK，API 文档完整 |
| **Cron** | cron + cron_parser | Desk 自动化 |
| **OAuth 凭据存储** | flutter_secure_storage | macOS Keychain / Win Credential / Linux libsecret |
| **i18n** | intl + .arb 文件 | Flutter 标配 |
| **系统托盘** | tray_manager | 同 leanflutter 家族，与多窗口插件配合好 |
| **全局快捷键** | hotkey_manager | 同上家族 |
| **自动更新** | auto_updater | electron-updater 等价 |

## 1.5 Pi SDK 替代方案设计（最大单项）

`@mariozechner/pi-coding-agent` 提供：
- 多 provider 抽象
- 工具调用（tool_use）解析
- Thinking 块处理（Claude）
- 流式 SSE 解析
- OAuth token 管理

Dart 端的 `lib/llm/` 设计：

```dart
// 核心抽象
abstract class LlmProvider {
  String get name;
  Future<bool> healthcheck();
  Stream<LlmEvent> chat({
    required List<Message> messages,
    required Model model,
    List<Tool>? tools,
    bool? thinking,
    CancelToken? cancelToken,
  });
}

// 事件流（sealed 强制 exhaustive switch）
sealed class LlmEvent {}
class TextDelta extends LlmEvent { final String text; }
class ThinkingDelta extends LlmEvent { final String text; }
class ToolCallStart extends LlmEvent { final String id, name; }
class ToolCallArgsDelta extends LlmEvent { final String id, argsJson; }
class ToolCallEnd extends LlmEvent { final String id; }
class MessageDone extends LlmEvent { final FinishReason reason; }
class LlmError extends LlmEvent { final String message; final int? statusCode; }

// 实现
class OpenAIProvider implements LlmProvider { /* HTTP + SSE */ }
class AnthropicProvider implements LlmProvider { /* HTTP + SSE + thinking */ }
class DashScopeProvider extends OpenAIProvider {}    // OpenAI 兼容
class VolcEngineProvider extends OpenAIProvider {}   // OpenAI 兼容
class MiniMaxProvider extends OpenAIProvider {}      // OpenAI 兼容
class CodexOAuthProvider extends OpenAIProvider {
  // 多了 device-code OAuth flow + token refresh + accountId 提取
}
```

OpenAI 兼容层让国内 5 家共用一套（参数微调通过 override `_buildRequest()` 实现）。剩下两个独立实现：
- **Anthropic**：SSE 事件类型不同（`message_start` / `content_block_delta` / `content_block_stop` 等），thinking 块嵌在 `delta.thinking` 里
- **Codex OAuth**：device-code flow（poll endpoint）+ token refresh（exp 字段判断）+ accountId 提取（这是 BUG-2 的根因）

## 1.6 性能与资源对比预期

| 指标 | Electron 现状 | Flutter (Option A) |
|------|--------------|---------------------|
| 安装包 | ~150 MB | **~60 MB** |
| 主窗口空载内存 | ~250 MB | **~80 MB** |
| 冷启动 | 3-5 s | **1-2 s** |
