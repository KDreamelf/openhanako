# 05 · 分阶段路线图与风险

## 5.1 路线图（Option A · 全 Dart）

不再有混合架构 phase，直接 4 阶段。每阶段给两个时间估算：
- **独立工程师纯人力**（无 AI 协助）
- **AI 高强度协助**（Claude Code / Cursor 等持续辅助）

### Phase 0 · Spike + 准备（人力 1-3 天 · AI 加速 4-12 h）

最小可跑路径：
- [ ] Flutter 项目骨架（推荐放 `flutter-migration-plan/prototype/` 或独立 repo）
- [ ] 安装核心依赖（见 [pubspec.yaml.template](./pubspec.yaml.template)）
- [ ] 跑通：单窗口 + Riverpod + dio 调 OpenAI HTTP 流式 + 显示一条对话
- [ ] 跑通：Drift 打开现有 `facts.db`（拷贝的副本）+ 列出 facts
- [ ] 跑通：desktop_multi_window 创建一个子窗口
- [ ] 跑通：tray_manager + hotkey_manager 各 1 个最简示例

**退出标准**：能在主窗口里跑通一次完整 OpenAI 流式对话；现有 facts.db 在 Drift 下可读。

  - [ ] CodexOAuthProvider（device-code flow + token refresh + accountId 提取）
- [ ] **OAuth 三种 flow**

  - [ ] authorization code（Anthropic，含本地 callback http server）
  - [ ] api key 直填
  - [ ] flutter_secure_storage 跨平台 + 降级

## 5.2 时间估算总结

| 阶段 | 独立工程师 | AI 加速 |
|------|-----------|---------|
| Phase 0 | 1-3 天 | 4-12 小时 |
| Phase 1 | 2-3 周 | 3-7 天 |
| Phase 2 | 2-3 周 | 3-7 天 |
| Phase 3 | 2-3 周 | 3-7 天 |
| Phase 4 | 1-2 周 | 1-3 天 |
| **小计** | **8-14 周** | **2-4 周** |

> **关于 "一晚上"**：Phase 0（spike）一晚上可达——这没问题；P1-P4 全部完成需要至少**专注 2-4 周**，即使有 AI 协助。原因：
> - **OAuth 调试**：每个 provider 的回调机制 / token 刷新 / accountId 提取都要本地实测；3 个 provider × 1 整天 = 3 天
> - **Pi SDK 行为对齐**：录制对话 + snapshot 对照 + 修补差异，1 周以上
> - **跨平台测试**：Win / macOS / Linux 各 1-2 天专门跑（高 DPI / 输入法 / 文件路径 / OAuth keystore）
>
> AI 写代码可能 10 分钟，但**跑通 OAuth 一次可能 1 小时**——这部分时间不可压缩。

## 5.7 推荐工作顺序优化建议（基于风险）

如果时间紧张，按风险加权排序：

```
1. Drift schema 定义 + 真实 db 兼容验证（最先做，避免后期返工）
2. Pi SDK 行为录制 + snapshot fixture（早做，给后面对齐用）
3. OpenAIProvider（最简单，建立模板）
4. AnthropicProvider（不同 SSE 协议）
5. CodexOAuthProvider（最复杂，留给最后）
6. core/ 各 Manager（依赖 LLM 层，所以排后）
7. Memory ticker（独立模块，可并行）
8. UI 层（在业务核心稳定之后）
9. 桌面集成（最后做）
10. 打包发布（最后）
```

## 5.8 何时该重新评估方案

如果 Phase 1 末（M1）出现以下情况，应**回头讨论是否需要部分回退**：
- Pi SDK 行为对齐 snapshot 测试覆盖率 < 80%
- 任意一个 provider 流式渲染有可见 bug 解决不了
- OAuth flow 在某平台完全打不通
- 跨 isolate 性能不达标（< 30 fps streaming）

**回退方案**：把无法搞定的模块用 FFI 调用预编译好的 Pi SDK 二进制（dart_eval / native code interop）。但这是最后手段。
